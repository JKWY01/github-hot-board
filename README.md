## 站点语言(16 种)

`/en /zh /zh-TW /ja /ko /de /fr /es /pt /it /ru /uk /pl /tr /vi /id`,根路径默认进英文(带 Accept-Language 时按浏览器语言挑)。全部 UI 文案逐语种成套(`app/[lang]/dict/`),SEO 每页带全语 hreflang + canonical,sitemap 覆盖 16 语 × 全榜。

行描述与抽屉 README 按站点语言取仓库自身的本地化版本(切换器解析 + 命名候选两级),读不到就诚实回退仓库原文。描述缓存在 `repo_desc` 表(仓库粒度),两条填充通道:浏览行为驱动(访客打开哪个语言就近补上,60 秒轮询自动送达)与同步期主动收割(每轮同步尾部按热度序扫描全部榜头仓库,一次拿齐 15 种语言,探测结论 30 天免重试;站点读取路径依旧只查库)。

> The site ships in 16 languages (default English). UI copy is fully translated per locale; row descriptions and the in-drawer README follow the repo's own localized files when available, falling back to the original text. Descriptions are cached per repo (`repo_desc`) and filled two ways — on demand by visitors, and proactively at the tail of every sync run (one sweep per repo covers all 15 locales; resolved probes are skipped for 30 days). The serving path always reads from the database only.


## 数据架构

一句话:**卖货的通道不进货。**

```
GitHub ──(只有同步任务碰)──> Neon Postgres ──(站点只 SELECT)──> 访客
```

- 同步任务(`lib/sync.ts`)顺序抓全部 34 个键(10 榜 + 语言分面),写两张表:
  - `board_head`:每个键的最新一拍,站点读它。插新的,前拍自然被覆盖。
  - `board_snapshots`:逐仓逐名次的明细行,本次同步是历史事实的存档。
- 触发方式:`npm run sync`(本地,需站点在跑)、`POST /api/sync`(带 CRON_SECRET)、
  GitHub Actions 每 30 分钟一轮(`.github/workflows/sync.yml`)。
- 站点渲染路径对 GitHub **零请求**。降级链:数据库 → 磁盘快照(本地 `.data/`,重建时不打 GitHub)→ 现场拉取。同步停太久时数据会旧,但不会假。
- Trending 页被风控挡住时,周榜/月榜内部自行换到 Search 口径补命,页面上如实标注,不糊弄。

### 往日榜

每次同步把完整榜单拍进 `board_snapshots`,所以任意一天切任意名字都能回看:

```
/zh/history/overall/2026-10-19
```

入口在 footer(往日榜 → 总榜)。历史拍只存排名、仓库和数字,不存实时简介;数据保留 `SNAPSHOT_RETENTION_DAYS`(默认 60 天)。页面 noindex,属工具页,不在 sitemap 里占道。

## 本地跑起来

```bash
npm install
cp .env.example .env.local
# 填 GITHUB_TOKEN / NEXT_PUBLIC_SITE_URL / DATABASE_URL(见下表)
npm run dev
```

| 环境变量 | 必填? | 说明 |
|---|---|---|
| `GITHUB_TOKENS` | 可选 | **多账号池**:`GITHUB_TOKENS=ghp_a,ghp_b,ghp_c`(逗号/空白分隔),一枚烧完自动换下一枚,取数节奏随池子规模等比放宽;不填则回落单枚 `GITHUB_TOKEN`,都没有走匿名降速 |
| `GITHUB_TOKEN` | 建议填 | classic PAT(不勾任何权限)或多枚时令其作为单枚兜底。Search API 从 60 次/时升到 5000 次/时 |
| `NEXT_PUBLIC_SITE_URL` | 部署时填 | canonical / sitemap / OG 用的最终域名 |
| `DATABASE_URL` | 部署时填 | Neon Postgres 连接串。表首次写入时自动建 |
| `CRON_SECRET` | 可选 | /api/sync /api/refresh 的门锁;`?only=榜名` 单榜重灌、`?boards=0` 只跑描述收割 |

本地调试开关:`GHB_FILL_DEBUG=1` 看读路(数据库命中还是水合),`GHB_SQL_DEBUG=1` 看发往库的 SQL。

## 部署

1. 在 [Neon](https://neon.tech) 建个项目,拿 Pooled connection 连接串。
2. Vercel 导入仓库,配四个环境变量(上表 + `CRON_SECRET` 自定义一个长随机串)。
3. 仓库 Actions secrets 配 `SYNC_URL`(你的域名 `/api/sync`)和 `CRON_SECRET`,30 分钟一次的同步就转起来了。
4. `https://域名/robots.txt` 里已有 sitemap 指向;搜索引擎控制台提交一次即可。

自托管也成立:`npm run build && npm run start`,数据面只要求能连上 Postgres,对Host/Vercel 无偏好。

## 诊断与运维

```bash
npm run sync                       # 本地手动拉一轮(30 榜,~4 分钟,一次重试)
```

同步是顺序慢跑(为控边界与限流),一轮约 4 分钟;30 分钟一次绰绰有余。明细行过 60 天自动清,`board_head` 只留最新,不需要人手干预。

## 市场分析(可选,与站点无关)

站点只服务榜单本身;历史维度的深挖走独立脚本 `scripts/market.mjs`,数据来自 GH Archive 公共镜像(约 10% 抽样,看形状用):

```bash
node scripts/market.mjs repo vercel/next.js --days 60   # 单仓库爆发日/拐点(自动兼容改名)
node scripts/market.mjs track agent --months 12          # 赛道趋势(新星数/活跃仓库数)
node scripts/market.mjs risers --days 30 --limit 15      # 涨星火箭榜
```

顺带一个探明的平台事实(2026-10):GitHub 已把 REST `stargazers`/`subscribers` 明细端点平台级撤下,逐星时间线只存在于事件归档里。仓库改名后归档仍按旧名存,查询需新旧名都算——`repo` 命令已处理。

## 如何新增一个榜

1. `lib/boards.ts`:写一个 `getXxxData()`,在 `getBoardData` 分发,`BOARD_META` 登记排行与排序语义。
2. `app/[lang]/dictionaries.ts`:补 `BoardCopy`(名称 / 口径 / FAQ,中英都要)。
3. 想有语言分面就在 `BOARD_META` 开 `facets`。
4. 路由、导航、footer、sitemap 随 `BOARD_ORDER` 自动生效,不手改。

## 已知限制,如实说

- Trending 数字在缓存期内(同步后 ≤30 分钟)可能与官方页面存在偏差。
- Search API 单查询 1000 条上限;总榜展示 Top 300,头部故事全覆盖。
- 黑红榜是结构化启发式(Fork/Issue 比例),页面已明示,请勿读成"情感评分"。
- 里程碑跨线检测发生在页面停留期间,服务器不留历史状态;想看"历史上谁跨过 1k",等往日榜攒几天再回看。
- 往日榜当前只存基准口径(全语言),语言分面的历史拍在库里,页面上还没有入口。
- 本项目与 GitHub 无官方关系,榜单仅为研究参考。
